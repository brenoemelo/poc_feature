# AI Context Map (Architecture & Codebase)

**Role:** This file serves as the **Primary Context** for AI Assistants (Trae, Cursor, Copilot).
**Goal:** Provide high-level understanding of the system, constraints, and locations of key information.

## 1. System Identity
- **Name:** Material Formulation System (PoC)
- **Tech Stack:** .NET 10 (Native AOT capable), AWS Lambda, DynamoDB, APIs Gateway.
- **Architecture:** Event-Driven Microservices (Clean Architecture).
- **Observability:** Centralized via `PoC.Observability` (OpenTelemetry + Native ILogger) -> Collector -> Tempo/Prometheus.
- **Features:** Managed via `PoC.FeatureFlags` (OpenFeature + Unleash Self-Hosted).

## 2. Key Directories
- `src/PoC.*`: Microservices (Materials, Costing, Populator).
- `src/PoC.Shared`: Shared Kernel (Results, DTOs, Infra filters). *Lightweight, no heavy dependencies.*
- `src/PoC.Observability`: Centralized OpenTelemetry & Logging configuration.
- `src/PoC.FeatureFlags`: Feature Flag provider (Unleash) & OpenFeature integration.
- `docs/architecture`: System Design & Diagrams.
- `docs/guides`: Coding Standards, How-To's.
- `scripts/`: Operational scripts (PowerShell & Python).
  - `scripts/services`: Service-specific automation (Build, Deploy, Test).
  - `scripts/utils`: Shared automation utilities (Logging, AWS Helpers).
  - `scripts/config`: Global configuration (Powershell `resources.ps1` & Python `global_config.py`).

## 3. Critical Constraints (The "Rules")
1.  **Strict Layering:** Domain calls nothing. API calls Application/Infra. Infra calls External.
2.  **No Exceptions:** Use `Result<T>` pattern for control flow.
3.  **No Offset Pagination:** Always use Cursor-based (Base64 token).
4.  **Observability:** All public methods must be instrumented. Logs must be structured.
5.  **Feature Flags:** Use `[WithFeatureGate]` (Declarative) over `if/else`.

## 4. Request Lifecycle
`Client` -> `APIGW` -> `Lambda` -> `Filter (Auth/Flag)` -> `Endpoint` -> `Validator` -> `Repository (DynamoDB)` -> `Response (Envelope)`

## 5. Development Workflow
1.  **Start Infra:** `docker compose up -d` (LocalStack + OTel + Flags).
2.  **Deploy:**
    - **Standard (Python + Terraform):** `python deployment/localstack/deploy_all_terraform.py` (Primary Method).
    - **Skip Build:** `python deployment/localstack/deploy_all_terraform.py --skip-build`.
    - **Deploy Specific Service:** `python deployment/localstack/deploy_all_terraform.py --service [materials|costing|populator|datahelper]`.
    - **Skip Destroy (During failures):** `python deployment/localstack/deploy_all_terraform.py --skip-destroy`
3.  **Test:** `.\scripts\tests\test_all_apis.ps1`
4.  **Debug:** Use `traceId` in Grafana Tempo.

### 5.1 Deployment Scripts Details
### 5.1 Deployment Scripts Details
- **`deployment/localstack/deploy_all_terraform.py`**:
    - **Master Orchestrator**: Manages the full deployment lifecycle for all services using Terraform.
    - **Status**: **PRIMARY & ONLY** supported deployment method. PowerShell scripts (`.ps1`) and legacy python deploy scripts are deprecated for deployment orchestration.
    - **Workflow**: For each service -> Validate -> Build (unless --skip-build) -> Deploy (Terraform init/apply).
- **`terraform/modules` & `terraform/services`**:
    - **Terraform Declarative Config**: All resources are defined declaratively to ensure idempotent deployments, replacing the old imperative AWS CLI commands.
- **`scripts/config/global_config.py`**:
    - **Single Source of Truth**: Central configuration for AWS resource names, ARNs, and Environment Variables.

### 5.2 Deprecated Scripts
- PowerShell scripts (`deploy-all.ps1`, `pipeline.ps1`) are **DEPRECATED** and should not be used for deployment. They may remain for reference or specific utility tasks but not for the main deployment flow.
