# Deployment Health Check Guide

This guide describes how to verify the health and status of the deployed microservices in the LocalStack environment.

## Prerequisites

- Docker must be running.
- The `poc_feature-localstack-1` container must be up.

## 1. API Gateway (Entry Point)

Verify that the API Gateway is running and routing requests correctly.

### List APIs
Find the `apiId` for your deployment.

```bash
docker exec poc_feature-localstack-1 awslocal apigateway get-rest-apis
```

Expected Output:
```json
{
    "items": [
        {
            "id": "bgl2ladyeo",
            "name": "Material Formulation API",
            ...
        }
    ]
}
```

### Test Connectivity
Use `curl` or PowerShell to hit the health check or list endpoint.

```bash
# The API ID is set to 'material-api' by default in the deployment scripts
curl http://localhost:4566/restapis/material-api/prod/_user_request_/api/v1/materials
```

## 2. Lambda Functions

### List Deployed Functions
Verify that all expected functions are deployed.

```bash
docker exec poc_feature-localstack-1 awslocal lambda list-functions
```

Expected Output should include:
- `PoC-Materials`
- `PoC-Costing`
- `PoC-Populator`
- `PoC-Materials-Ingestion` (Worker for async population)
- `PoC-Populator-Worker` (Worker for job processing)

### Get Function Configuration
Check the configuration of a specific function, including environment variables and handler settings.

```bash
# Materials Service
docker exec poc_feature-localstack-1 awslocal lambda get-function --function-name PoC-Materials

# Costing Service
docker exec poc_feature-localstack-1 awslocal lambda get-function --function-name PoC-Costing

# Populator Service
docker exec poc_feature-localstack-1 awslocal lambda get-function --function-name PoC-Populator
```

### Get Function Policy
Check if the function has the necessary resource-based policies (e.g., allowing public access via Function URL).

```bash
docker exec poc_feature-localstack-1 awslocal lambda get-policy --function-name PoC-Materials
```

### Get Function URL
Retrieve the HTTP endpoint for the services.

```bash
docker exec poc_feature-localstack-1 awslocal lambda get-function-url-config --function-name PoC-Materials
docker exec poc_feature-localstack-1 awslocal lambda get-function-url-config --function-name PoC-Costing
```

## 2. Logs (CloudWatch)

To debug issues, you can view the logs generated by the Lambda functions.

### List Log Groups
Identify the log groups created by the Lambda functions.

```bash
docker exec poc_feature-localstack-1 awslocal logs describe-log-groups
```

### View Recent Logs
Tail the logs for a specific function to see real-time output or recent executions.

```bash
# View logs for PoC-Materials
docker exec poc_feature-localstack-1 awslocal logs tail /aws/lambda/PoC-Materials --follow

# View logs for PoC-Costing
docker exec poc_feature-localstack-1 awslocal logs tail /aws/lambda/PoC-Costing --follow

# View logs for PoC-Populator
docker exec poc_feature-localstack-1 awslocal logs tail /aws/lambda/PoC-Populator --follow

# View logs for Worker Lambdas
docker exec poc_feature-localstack-1 awslocal logs tail /aws/lambda/PoC-Materials-Ingestion --follow
docker exec poc_feature-localstack-1 awslocal logs tail /aws/lambda/PoC-Populator-Worker --follow
```

> [!TIP]
> **Advanced Tracing & Correlation:** The system now uses structured OTLP logging. For a detailed guide on how to link logs to traces and monitor performance metrics, see the [Observability Guide](observability.md).

## 3. Asynchronous Messaging (SQS & SNS)

Verify the event-driven infrastructure.

### List SNS Topics
Ensure the topics for domain events exist.

```bash
docker exec poc_feature-localstack-1 awslocal sns list-topics
```

### List SQS Queues
Ensure the queues for processing events exist.

```bash
docker exec poc_feature-localstack-1 awslocal sqs list-queues
```

### Check Queue Depth
Check if messages are piling up in the queues (indicating consumers are not processing them).

```bash
# Replace QUEUE_URL with the url from list-queues
docker exec poc_feature-localstack-1 awslocal sqs get-queue-attributes \
    --queue-url http://sqs.us-east-1.localhost.localstack.cloud:4566/000000000000/materials-queue \
    --attribute-names ApproximateNumberOfMessages
```

## 4. Database (DynamoDB)

Verify that the data persistence layer is active.

### List Tables

```bash
docker exec poc_feature-localstack-1 awslocal dynamodb list-tables
```

Expected tables:
- `materials-table`
- `costing-prices-table`

### Scan Data (Sample)
Check if data is being written to the tables.

```bash
# Check Materials
docker exec poc_feature-localstack-1 awslocal dynamodb scan \
    --table-name materials-table \
    --limit 1

# Check Prices
docker exec poc_feature-localstack-1 awslocal dynamodb scan \
    --table-name costing-prices-table \
    --limit 1
```

## Common Troubleshooting

- **Function not found**: Ensure you ran the deployment scripts (`deployment/localstack/deploy-all.ps1`).
- **403 Forbidden on Function URL**: Ensure the function has a resource-based policy allowing `lambda:InvokeFunctionUrl` from principal `*`. Check with `get-policy` command.
- **Connection refused**: Ensure the Docker container is running (`docker ps`).
- **Logs empty**: Trigger the function via an API call or event first.
